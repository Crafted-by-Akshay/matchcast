## Changed paths and design decisions

* `packages/contracts/matchcast_contracts/schemas/v1.json`: the canonical Draft 7 wire schema. Six top-level kinds cover roster context, typed event envelopes, tracking frames, state references, claims, and publications. Initial wire version is `1.0.0`, distinct from requirements document version v1.1.
* `packages/contracts/src/generated.ts` and `scripts/generate.mjs`: deterministic TypeScript generation from that JSON only. `--check` detects drift. No separately maintained Pydantic/TypeScript wire models exist.
* `packages/contracts/src/index.ts` and `matchcast_contracts/__init__.py`: Ajv and Python jsonschema validation of the same schema, plus matching contextual checks. Unknown players require a supplied roster; pitch bounds, stream membership, correction target/current revision, evidence limits, approved claim references, and current publication state are checked explicitly.
* `packages/contracts/fixtures/`: shared examples and failure corpus. They include own goals, correction/retraction branches, complete/sparse tracking, event/interval evidence, Tamil text, and explicit caption-only audio ID nullability. Example numeric values and approval flags are synthetic test inputs, not measured or independently approved football facts.
* `packages/contracts/scripts/roundtrip.mjs` and `matchcast_contracts/__main__.py`: JSON stdin/stdout bridges used for real cross-process serialization checks.
* `packages/contracts/package.json`, `pyproject.toml`, `tsconfig.json`, `eslint.config.mjs`, and package README: minimal locked workspace tooling; the old `.gitkeep` is removed.
* `tests/contracts/`: the same positive/negative/context fixture cases in both languages, TypeScript compile-time negative examples, and two-direction cross-language transport tests.
* Root npm/uv manifests and locks, Makefile, and README: install/register the contracts package and include its lint, typecheck, build, tests, and generated-type drift check in normal commands. No existing npm package version changed; the five known development audit findings remain.
* `docs/contracts.md`: units, match clock, identity/order, correction/retraction/state semantics, evidence/publication obligations, versioning, and compatibility rules. `S02-validation.log` retains actual command output and first-failure diagnostics.

Closed schemas and exact-version dispatch reject unknown fields/variants/versions.
Both validators preserve values and reject rather than coerce. Source/reference
metadata inherits the enclosing stream. A correction gets its own immutable
control ID/sequence and identifies the original event ID/sequence and next logical
revision; a materialized corrected event retains the original identity. Publication
context checks current state and approved referenced claims, but does not fabricate
approval authority, factual recomputation, or an existing audio asset.

## Hash method

Source paths are the sorted unique entries from
`git ls-files -z --cached --others --exclude-standard`, excluding `docs/evidence/`
and nonexistent deleted placeholders. For each existing file, SHA-256 receives
UTF-8 repository-relative path + NUL + raw contents + NUL. The fixture corpus hash
uses the same method restricted to `packages/contracts/fixtures/`. The schema hash
is SHA-256 of its raw file bytes. The local configuration hash uses the same
path/content method over exactly these paths:

