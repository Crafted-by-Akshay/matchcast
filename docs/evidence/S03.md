A live-process probe launched Uvicorn three times with the MatchCast environment
variables explicitly cleared or set as shown. Each process started, answered
`/health`, answered `/ready`, and logged orderly Uvicorn shutdown after SIGTERM:

| Process environment | `/health` | `/ready` | Model status |
| --- | --- | --- | --- |
| all MatchCast variables unset | HTTP 200, healthy | HTTP 200 | `local_mock` |
| `MATCHCAST_MODE=cloud`, endpoint/key unset | HTTP 200, healthy | HTTP 503 | `unavailable` |
| cloud mode, HTTPS endpoint and placeholder-only key | HTTP 200, healthy | HTTP 503 | `pending` |

The third case uses `https://example.invalid/model` and the literal
`placeholder-only`; the application did not connect to it. Full command output
is in `docs/evidence/S03-validation.log`. The `uv` wrapper returned 143 after
SIGTERM in each probe; Uvicorn logged `Application shutdown complete` before
exit. This is the expected wrapper result after terminating the foreground
server, not a failed startup or an asserted clean wrapper exit code.

The top-level `ready` status means only that the local profile can serve with
local substitutes. Each dependency has its own state; local substitutes are
`local_mock`. `pending` means valid cloud configuration lacks an adapter/probe,
and `unavailable` means configuration is invalid or incomplete. Dependency
`ready` is reserved for a future adapter after its real provider probe succeeds;
no current cloud configuration can claim it.

## Initial failures and repairs

The first focused test attempt exposed two issues: invalid-mode diagnostics used
internal field names, and FastAPI attempted to serialize a raw `NaN` input while
returning a 422. Diagnostics now name the environment variable, and request
validation responses omit raw input/context. A first Ruff run also found import
ordering and line-length issues. Those were fixed. The final focused and full
checks above passed; the validation log preserves final commands/results.

## Limitations and review state

The in-memory registry loses state on process restart and does not share state
across API replicas. Session identity handling is not authentication or tenant
authorization. The cloud model adapter and real dependency probes do not exist;
valid cloud configuration therefore remains visibly `pending`, and invalid
configuration is `unavailable`. A local mock store does not pass durability,
security, deployment, cold-recovery, performance, or integrated production
readiness gates. No cloud resources or provider units were used.
