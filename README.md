# MatchCast

MatchCast is an AI production crew for a live football broadcast. It turns a stream of synthetic football events into explainable match intelligence: live commentary lines that each carry the evidence behind them, a verifier that recounts every number before a line goes on air, and views that change for a data-hungry analyst, a casual fan and a producer. Built for Microsoft's "Inside the Game" hackathon, multi-agent category. The teams are real national teams with real past results as reference facts (ADR-0020); every player and every match event is fictional and generated by our own simulator.

> **Status (26 Oct 2026, from `/v1/status` and `docs/infra.md`):** the app runs on Azure Container Apps (East US 2) with a deployed agent api. Live: Producer, Analyst, Narrator and Verifier on the gpt-5-mini deployment (the Producer picks among rules candidates; quiet moments (priority 3, set by `MATCHCAST_LIVE_MAX_PRIORITY`) go straight to the rules Analyst and Narrator, and each agent's rules twin takes over if a call fails), the Stats Desk, Table Storage, AI Search, Speech, Translator, Vision, Content Safety and Entra sign-in on the Producer routes. Simulated: Event Hubs, which is an in-process stream today. Planned, not connected: Microsoft Fabric and Azure Databricks. `/v1/status` on the api and the **Status** button in the app list what is live, simulated or planned; that endpoint is the source of truth.

## Try it

- **Live demo:** <https://ca-web-matchcast-dev.calmbay-045566e2.eastus2.azurecontainerapps.io> (anonymous viewing; the first load can take up to a minute while the app wakes). Status and the Planned list: [`docs/judge/walkthrough.md`](docs/judge/walkthrough.md).
- **Sign-in:** nothing needs a sign-in to watch, use the Analyst view or use the Broadcast view. Approving, editing or killing a line on the Producer routes goes through Entra ID sign-in on the api; the rest of the app works without it.
- **Locally in about two minutes:** see [Run locally](#run-locally). It needs no cloud account.

Three things to click once it is open:

1. **Watch** view: the match starts on load. Pick Casual or Analyst in the Feed picker (or a watch mode: My club, Player focus, One metric) and see the same moment explained differently; pick one of ten languages in the header.
2. Press **Why?** or **How was this made?** on any line: the claim, its cited events and each agent's step.
3. **Crew** pill (Agents tab): the spawn tree of the specialists each goal called, and the scoreboard. Then **Seed a bad claim** (the Verifier rejects a wrong number and repairs it from the raw event log) and **Cut the model** (the rules twins take over mid-match and the lines keep coming).

## Multi-agent design

Four agents with separate jobs: **Producer** (picks moments, routes lines, asks for approval), **Analyst** (events to claims with evidence), **Narrator** (claim to line), **Verifier** (recounts every claim from the raw event log, repairs once or abstains). They run as a Microsoft Agent Framework graph. The Predictor is a deterministic tool and the Data Scientist runs on demand. Claims and lines carry hashes and a tamper-evident audit chain (`matchcast.audit/1`).

The production crew around them, as merged on 26 Oct:

- **Specialists.** On a goal or red card the Showrunner planner spawns up to five specialists in parallel (replay, tactics, stats, rhythm, head-to-head history), at most one on any other moment. Each reports findings with the event ids (or result rows) they rest on, so the Verifier can recount them; specialists never write a line. The spawn tree shows on the Crew panel. The routing decision is still the Producer's; a separate Showrunner model call is not built.
- **Verifier gate and repair.** Recount, then an adversarial pass of five falsification attempts, then one repair (a number goes back to the Analyst, wording to the Narrator). A booth line that fails its repair on a checkable fact (a number, a player, a source, stale state) waits for the producer flagged as escalated, and can only be killed; any other line that fails is dropped from air.
- **Approval as a mode.** In producer mode the two booth voices (play-by-play and colour) wait for one producer's approval after the Verifier. The derived feeds never wait: they air once verified, or are dropped.
- **Six feeds.** Casual, analyst and catch-me-up (on request, in the viewer's language) are on the Watch screen. The news ticker and audio description air on the api's derived lane and show on the producer's six-up monitor; Watch tags them **Planned** until viewers see them. The half-time explainer is written and verified but not aired (**Planned**).
- **Shared memory and replan.** Storylines from verified lines reach the Producer and Narrator with numbers masked; 60 s with no verified line makes the Showrunner replan once and open a player's storyline, which that player's next goal pays off once. The replan assigns the replay specialist but does not run it yet (**Planned**).
- **Failure drill.** **Cut the model** on the Agents tab cuts one match's model; the rules twins take over (ADR-0014) and each fallback is audited. **Restore the model** brings it back after the breaker's 30 s.
- **Event → on air.** A header pill shows the median wall time from a Watch event reaching the app to its verified line arriving in the browser.

Details, packet shapes and the repair path: [`docs/architecture/04-agents.md`](docs/architecture/04-agents.md).

## Evaluation

`eval/compare.py` compares a single agent against the four-agent workflow on the same frozen moments with a judge that does not use the Verifier; its recorded numbers come from an offline run with a seeded stand-in model, so they prove the harness, not model quality ([`eval/README.md`](eval/README.md), [`eval/results/offline.json`](eval/results/offline.json)). The in-app crew scoreboard runs three rules-mode arms on one fixed fixture with the same seeded wrong claims (full crew, a single agent with no Verifier, the crew with the Verifier bypassed) and grades each aired line against the simulator's truth ([`docs/architecture/16-testing-and-quality.md`](docs/architecture/16-testing-and-quality.md) §4.1); it is labelled Rules-only, and a recorded model run is shown beside it only when one exists for that fixture.

**Verifier, measured (rules mode, offline).** `eval/agents_eval.py` replays the 34 lines the workflow verified on the frozen match `match-short`, changes each one in one way (151 content mutations: a wrong number, an invented player, a player from the other club, a claim citing an event that is not in the log, and so on) and asks the Verifier again. It caught **99.3%** of them, and only a rejection for the intended reason counts as a catch; it rejected **0 of the 34 honest lines**. The seeded bad claim was injected at 7 match times and rejected for the right reason in 7 of 7, and no wrong claim reached a screen. Scope: the deterministic rules agents on one fixture, so this is the floor a model-written line is checked against, not a measure of model quality. Full table: [`docs/eval/agents-eval.md`](docs/eval/agents-eval.md). The Watch screen's Verifier chip shows the same 99.3% and opens the Verify tab.

**Live run on Foundry (26 Oct, gpt-5-mini).** The same harness against the Foundry-backed Analyst, Narrator and Verifier, on a smaller replay (16 verified lines, so 69 content mutations and 19 honest lines; [`docs/eval/agents-eval-live.md`](docs/eval/agents-eval-live.md)), with **0** model calls falling back to the rules: the seeded bad claim was caught 7 of 7 with 0 wrong claims shown, **100%** of the 69 mutations were caught for the right reason, 100% of 26 claims matched an independent recount, and **94.1%** of 17 Narrator first drafts stayed inside their claims and the roster (83.3% on 25 Oct). Ask, which has no model, answered 40 of 40 golden questions and stopped all 20 red-team prompts. The weak spots, from the same run: the Verifier still rejected **15.8%** of 19 honest lines (46.2% on 25 Oct), so it errs towards holding a line; 12.5% of 8 booth colour drafts were generic (a kind of line the Verifier refuses); numbers in the wrong order (0-1 for 1-0) are not caught. End to end on the frozen match ([`eval/results/live.json`](eval/results/live.json), one run), the live system aired a line on 7 of 22 moments with 0 wrong lines and a median of 6.3 s per moment, where the rules-only crew airs 14; a single gpt-5-mini agent with no Verifier aired all 22 at 1.9 s, and the judge found no wrong line in them either, so this clean match shows no accuracy edge for the crew. What the crew adds is a check: it caught all 7 seeded bad claims and all 69 planted errors, and the single agent has no such step. The two were not compared head to head on those errors.

## Production crew: what is Planned

- **Half-time explainer as a feed**, and the **ticker and audio description on the Watch screen**: written and verified, not shown to viewers yet.
- **Arabic voice**: the ten feed languages are translated and re-checked; only English, Spanish, Portuguese and Hindi are voiced.

- **CREW-4.4 model adversary** (board AB#422): **Planned**. The story sends claims the rules cannot recount to a model adversary, but every metric the code emits already has a deterministic recount (`verify/checks.py`), so no claim reaches it yet. Which claims go to the model, and which tools it gets, is a decision still open.
- **Storylines**: the payoff covers goals only, and the specialist a replan assigns is recorded, not run ([`docs/architecture/04-agents.md`](docs/architecture/04-agents.md)).

## Responsible AI

Every published line passes the Verifier; in producer mode the booth lines also wait for a human approval, and the derived feeds air only once verified. A local screen checks text (Azure Content Safety screens lines when its endpoint is set; `/v1/status` shows whether it is live), a red-team set is kept in `eval/`, and all people and clubs are fictional. See [`docs/responsible-ai.md`](docs/responsible-ai.md) and [`docs/architecture/14-security-and-responsible-ai.md`](docs/architecture/14-security-and-responsible-ai.md).

## Run locally

Prerequisites: Node.js `^20.19.0`, `^22.13.0` or 24+, `uv`, Python 3.12 (`uv` can fetch it). No cloud credentials needed.

```sh
make install                 # npm ci and uv sync from the lockfiles
node tests/e2e/serve.mjs     # builds apps/unified and serves it at http://localhost:4173
```

Optional, for server-side agent lines instead of the in-page rules fallback, in a second terminal:

```sh
MATCHCAST_MODE=local MATCHCAST_AGENT_MODE=rules \
  uv run --locked --package matchcast-api uvicorn app.main:app --app-dir services/api --port 8000
```

then build the app with `python3 apps/unified/build.py --api http://localhost:8000` (see [`apps/unified/README.md`](apps/unified/README.md)). API configuration and endpoints: [`docs/backend.md`](docs/backend.md).

Checks, the same ones CI runs:

```sh
make lint typecheck test build   # or: scripts/local_ci.sh
make e2e                         # Playwright
```
